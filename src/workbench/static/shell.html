jura.sh workbench alpha

Install or update before you rely on this window:
    Run `jura setup` in a terminal: it installs what is missing and asks before sudo. `jura doctor` lists every tool.

    A prototype legal engineering workbench: one window per legal case, where you write the case with agents, next to its evidence and its anonymization.

    It makes bids on five open problems:

    • Accurate quoting and citing. Quotes are the source's own bytes, from labelled evid snippets, never model wording.
    • Local and frontier models together. Local models handle the personal data. Frontier models only see the anonymized case.
    • Annotation above the document level. Notes on the case tree's folders and files as well as its lines, queued to agents.
    • Automatic version tracking. Every change is committed in the background. Tag a state to mark it.
    • Multi-harness collaboration. Several agent harnesses (claude, codex, opencode, …) work side by side on one case.
    Write
    The case workdir: edit and annotate files, a Typst editor with live preview, and sandboxed terminals for agents. Every change is committed.
    Datasets
    evid: documents, labels and search.
    Anonymization
    did: the raw case files stay here, outside the case. Only the anonymized PDFs reach the case.

    This is an alpha prototype. Features, file formats and behaviour will change, and things will break. Keep your own backups, and review everything an agent writes before you rely on it. The workbench gives no legal advice.

    Ctrl+PageDown / Ctrl+PageUp cycles the tabs. Ctrl+W or Ctrl+Q quits the window.

    Start a case

    A case is a folder on this machine, tracked in git. Its map, main.typ, states the question. Pick what it starts with; you can change all of it.
